Reading these numbers honestly.

This machine is running three other build sessions today, and the local harness is
BIMODAL as a result: the same untouched PO-04 page, on the same branch build, measured
77 (TBT 270 ms) and then 32 (TBT 2,880 ms) minutes apart. The baseline stayed at 76 and
75 across the same interval. So the low branch runs are machine load, not the page:

  - PO-04 is NOT touched by this branch, yet it moves across the same range, which no
    change here could cause.
  - Branch and baseline serve byte-identical HTML for that page (559 KB) and an
    identical 129 KB __NEXT_DATA__. The whole client-JS delta is +69 KB (2,738 vs 2,669
    KB across 21 chunks) - PO-05's copy pack and asset map joining the shared route
    bundle. 69 KB cannot move TBT by two and a half seconds.
  - Production serves that same 574,583-byte page at TBT 40 ms.
  - The branch's own best run (77 / TBT 270 ms) is level with the baseline's (76 / 210 ms).

CLS is 0 on every branch run, including the design lock, and 0.015 on the baseline -
the 4:3 Section 3 files carry explicit width and height that now match the panel box
exactly, so nothing shifts as they load.

Conclusion: no performance regression is attributable to PO-05. Any single local score
below ~70 on this machine today should be read against a same-minute baseline run, not
against the 70/69 pair recorded earlier when the box was quiet.
