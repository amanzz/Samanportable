  Reading
  -------
  CLS is 0.0000 on all three targets, every run. TBT is within noise of the lock
  (flatpack median 525 ms, porta-cabins local 540 ms, porta-cabins live 521 ms).

  LCP: flatpack 4312 ms median against porta-cabins 3460 ms on the same machine and
  the same server, and against 5176 ms on live production. So this page is ~850 ms
  slower than the local design lock and ~860 ms faster than the live one.

  The ~850 ms against the local lock is attributable to the image optimizer, and it
  is a consequence of the asset map's public paths, not of this page's markup:

    src/lib/imageSrc.ts isPreOptimizedLocalImage() bypasses /_next/image ONLY for
    /images/products/**.webp. The signed asset map paths this pack's 55 assets at
    /images/flat-pack-container-homes/..., outside that prefix, so every one of them
    is re-encoded by the optimizer on first request. The T12 comment in that file
    records the measured cost of exactly this: "the origin re-encodes an already-
    optimal WebP on the first request for each (w,q) variant, and Cloudflare does
    not cache /_next/image (every response is cf-cache-status: MISS), so the first
    paint of every product/size image pays a multi-second optimizer TTFB."

    These 55 files are already at final size and quality (86.2 to 119.8 KB after the
    C2PA chunk is stripped), i.e. exactly the class that rule was written for.

  Recommended, but NOT done in this build because it needs SAMAN to amend the signed
  asset map: re-path the pack under
      /images/products/container-houses/flat-pack-container-homes/...
  matching prefab-container-homes. That single change bypasses the optimizer, makes
  the files CDN-cacheable by extension, and also makes verifier line 257 reachable
  (see README gap 2). It cannot be done unilaterally: `public_path` is stated 55
  times in the asset map and the verifier asserts each one against the served HTML.
